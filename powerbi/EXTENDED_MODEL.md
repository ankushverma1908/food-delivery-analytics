# Extended Power BI Model

Run the following from the repository root after installing requirements:

```bash
python src/generate_extended_data.py
```

This creates synthetic supporting tables in `data/extended/`. It does not overwrite the original CSVs.

## Tables to import

| File | Grain | Purpose |
|---|---|---|
| FactOrders.csv | One row per order | Existing order-level measures |
| DimCustomer.csv | One row per customer | Customer attributes |
| DimRestaurant.csv | One row per restaurant | Restaurant and cuisine attributes |
| DimDate.csv | One row per date | Calendar analysis |
| FactOrderItems.csv | One row per order line | Product mix, basket size, item revenue |
| DimMenuItem.csv | One row per menu item | Menu/category attributes |
| FactDelivery.csv | One row per order | Partner, distance, prep and travel analysis |
| DimDeliveryPartner.csv | One row per partner | Partner attributes and rating |
| DimPromotion.csv | One row per promotion | Campaign attributes |
| BridgeOrderPromotion.csv | One row per redeemed order promotion | Promotion-to-order mapping |

The first four tables are generated by `src/prepare_powerbi_data.py`. The additional five files are generated by `src/generate_extended_data.py`.

## Relationships

Create single-direction relationships:

- DimDate[DateKey] 1 → * FactOrders[DateKey]
- DimCustomer[customer_id] 1 → * FactOrders[customer_id]
- DimRestaurant[restaurant_id] 1 → * FactOrders[restaurant_id]
- FactOrders[order_id] 1 → * FactOrderItems[order_id]
- DimMenuItem[menu_item_id] 1 → * FactOrderItems[menu_item_id]
- FactOrders[order_id] 1 → 1 FactDelivery[order_id] (or 1 → * if you later model multiple delivery attempts)
- DimDeliveryPartner[delivery_partner_id] 1 → * FactDelivery[delivery_partner_id]
- FactOrders[order_id] 1 → * BridgeOrderPromotion[order_id]
- DimPromotion[promotion_id] 1 → * BridgeOrderPromotion[promotion_id]

Keep promotion analysis separate from item revenue to avoid multiplying order-level revenue when a visual combines item lines and promotion bridge rows.

## New report opportunities

### Menu & Basket Analysis
- Revenue by menu item and item category
- Quantity sold by item
- Average items per order
- Top products within each cuisine
- Basket composition by city

### Delivery Partner & Operations
- Average prep time and travel time
- Delivery distance distribution
- Partner rating and completed delivery volume
- Delivery time by distance band and city
- Delayed-order share by city

### Campaign Effectiveness
- Promotion redemptions
- Discount amount by campaign
- Average order value by coupon
- Delivered revenue associated with orders using a promotion

## Important interpretation notes

- Every added table is synthetic portfolio data. It is not sourced from Swiggy, Zomato, or actual delivery partners.
- Order-item line totals are allocated to reconcile to the existing order_value. They are simulated line allocations, not observed product prices.
- Delivery partner, distance and event timestamps are simulated. For completed/delayed orders, prep plus travel time reconciles to the source delivery_time_mins. Cancelled orders have a cancellation timestamp and no assigned partner.
- Coupon labels are inferred from the existing discount percentage bands. They are synthetic campaign labels, not original recorded coupon codes.
- Use delivered orders for realized revenue. Keep cancelled and delayed statuses visible as operational outcomes.
